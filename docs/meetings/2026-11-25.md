# 2026-11-25 통합 기획 회의록

일시: 11/25(수) · 참석: Team 10 (4K) · 다룬 것: 통합 결정 이슈 여섯 개([#39](https://github.com/4kmba/ltc-caregivers/issues/39)～[#44](https://github.com/4kmba/ltc-caregivers/issues/44))와 디자인 방향
배경: [통합 제품 기획안](../2026-11-19-integration-plan.md), [통합 돌봄 플랜 스펙](../specs/spec-integrated-care-plan.md)

## 요약

- 여섯 이슈를 모두 정했습니다. AI는 추천안 (가)대로 쓰고, 제품 이름은 "돌봄수첩"입니다.
- 처음부터 다룰 상황은 일곱 개입니다. 회의에서는 4～5개로 시작하고 더 필요하면 늘리자고 했고, 회의 뒤 정리하면서 김영균이 후보 일곱 개를 모두 넣기로 정했습니다.
- 할 일 카드와 질문·답의 검수는 유정민, 백민경, 한수연 세 사람이 상황별로 나눠 맡습니다.
- 서버와 API 비용은 김영균이 맡습니다.
- 화면은 미니언 옐로 계열의 밝은 노랑을 주색으로 쓰되, 글자가 잘 읽히고 디자인이 싸 보이지 않게 만듭니다.

## 결정

| 이슈 | 정한 것 |
|---|---|
| 1. AI를 어디에 쓸까 (#39) | 추천안 (가). AI는 보충 질문 만들기, 할 일 카드 고르고 "왜 지금" 쓰기, 카드에 적힌 답을 상황에 맞춰 풀어 쓰기, 의료 질문을 "의료진에게 물어볼 질문"으로 바꾸기를 맡습니다. 돌봄 방식 비교는 AI가 쓰지 않습니다. |
| 2. 응급 안내 (#40) | 첫 화면에서 묻지 않습니다. 보호자가 직접 적은 글에 위급 신호가 있으면 목록보다 먼저 안내합니다. 모든 화면 아래에 "즉시 도움이 필요할 때" 링크도 둡니다. |
| 3. 처음 다룰 상황 (#41) | 일곱 개: 낙상, 증상 악화, 입원·퇴원, 잘 모르겠어요, 등급 직후, 주 보호자가 돌볼 수 없게 됨, 기억력이나 행동이 걱정돼 알아보는 중. 시설 검토는 P1, 이용 기관 문제는 P2로 둡니다. |
| 4. 제품 이름 (#42) | 돌봄수첩. 같은 이름의 서비스나 상표가 있는지는 아직 확인하지 않았습니다. |
| 5. 담당과 검수 (#43) | 할 일 카드 45장과 질문·답 180개를 유정민, 백민경, 한수연이 상황별로 나눠 검수합니다. 누가 어느 상황을 맡을지는 세 사람이 정합니다. 카드를 상황별로 다시 나누는 일은 김영균이 합니다. |
| 6. 서버 (#44) | 서버를 올리고 관리하는 일과 API 비용은 김영균이 맡습니다. |

3번은 회의에서 정한 범위(4～5개)보다 넓고, 검수할 양이 카드 거의 전부로 늘어납니다. 스펙에는 이미 두 사람이 확인하지 않은 내용은 화면에 내지 않는다는 규칙이 있어, 검수를 마치지 못한 상황은 그 규칙대로 빠집니다.

## 디자인 방향

- 주색은 팬톤 13-0851 TCX Minion Yellow 계열입니다. 스와치에서 뽑은 값은 `#FED65C`입니다.
- 이 노랑 위에 흰 글자를 올리면 대비가 약 1.4:1이라 읽기 어렵습니다. 노랑은 배경과 강조에 쓰고, 글자는 진한 먹색으로 씁니다.
- 접근성 기준(색 대비 WCAG AA, 누르는 곳 44px 이상, 글자 크게, 어두운 화면)은 스펙에 적은 그대로 지킵니다.
