## 한 줄 제안

네 프로토타입을 나란히 붙이지 않고, 보호자가 거치는 한 흐름으로 다시 짭니다. 보호자가 **상황을 고르고 몇 가지에 답하면, 고를 수 있는 돌봄 방식 2～3개를 비교하고, 고른 방식에 맞는 할 일을 시점별로 받습니다.** 할 일마다 연락처, 출처, 물어볼 질문과 답이 붙고, 상황이 바뀌면 바뀐 답만 고쳐 다시 받습니다.

이 흐름은 `PROJECT.md`의 가설("상황이 바뀔 때마다 선택지를 다시 정리")과 10/28 회의에서 가깝다고 본 방향("상황이 바뀌면 할 일과 연락할 곳을 한 장으로")을 함께 담습니다. 설문에서 가장 필요했다고 답한 도움 세 가지와도 순서대로 맞습니다. 공공 지원·제도 안내(17명 중 10명)는 할 일에 붙는 지원과 연락처가, 지금 무엇을 결정해야 하는지 정리(8명)는 할 일 목록이, 선택지별 장단점과 비용 비교(6명)는 돌봄 방식 비교가 맡습니다.

## 기능을 겹치지 않게 나누기

기능을 "누가 만들었나"로 묶으면 겹칩니다. 그래서 보호자가 차례로 하는 일 여섯 가지와, 모든 단계에 똑같이 적용되는 공통 규칙으로 나눴습니다. 프로토타입의 기능은 모두 이 가운데 한 칸에만 들어갑니다.

## 만드는 방법

**내용과 화면을 나눕니다.** 네 프로토타입에 내용이 `cards.json`, `data.js`, `sources.json`, HTML 안에 따로 들어 있습니다. 통합 제품은 내용을 다섯 파일로 모으고 화면은 그 파일을 읽기만 합니다. 팀원이 코드를 건드리지 않고 내용만 고쳐 PR을 올릴 수 있습니다.

| 파일 | 담는 것 | 어디서 옮기나 |
|---|---|---|
| 상황과 질문 | 상황 카드, 기본 정보, 상황별 질문 | 세 사람의 질문을 합침 |
| 돌봄 방식 | 상황별 선택지, 장단점, 비용 기준, 가족 부담, 지켜볼 신호 | 백민경 `data.js` |
| 할 일 카드 | 할 일, 이유, 조건, 붙는 질문 | 김영균 `cards.json` |
| 질문과 답 | 질문, 답, 주제, 자료 번호 | 김영균 카드에 붙은 55개 + 한수연 15개 |
| 자료 목록 | 이름, 링크, 전화번호, 확인한 날짜 | 유정민 `sources.json`에 나머지 연락처를 더함 |

**김영균 HW6 버전에서 출발합니다.** `main`의 `prototypes/김영균/`에는 후보 카드를 거르는 규칙, AI 호출 세 가지, AI가 실패했을 때 규칙 목록으로 바꾸는 처리, 인터뷰 사례 5건 점검이 이미 있습니다. Node 서버가 화면을 내보내고 API 키를 서버에만 둔 채 Claude를 부르는 구조입니다. 여기에 돌봄 방식 비교, 자료 목록, 주제별 질문 화면을 붙입니다.

**AI는 확인한 카드 안에서만 움직이고, 꺼져도 제품이 돕니다.** 코드가 조건으로 후보 카드를 먼저 거르고, AI는 그 안에서만 고릅니다. 연락처와 링크는 AI가 쓰지 않고 화면이 자료 목록에서 꺼냅니다(유정민 님의 방식). AI가 답하지 못하면 규칙이 고른 목록과 카드에 적힌 답 원문을 보여 줍니다. AI에게 어디까지 맡길지는 팀이 정할 것 1번입니다.

**새 폴더에 만듭니다.** 개인 프로토타입은 HW6 제출물이라 그대로 두고, 통합 제품은 `app/` 같은 새 폴더에 둡니다. 저장소 규칙대로 `docs/specs/spec-<기능명>.md`를 먼저 PR로 확정한 뒤 개발합니다.

## 팀이 정할 것

추천을 함께 적었지만, 결정은 팀 회의에서 합니다.

1. **AI를 어디에 쓸까.** 과목 이름이 AI 기반 비즈니스이고 `PROJECT.md`도 AI 어시스턴트라, 데모에서 AI가 하는 일이 보여야 합니다. 한편 인터뷰한 9명 중 4명은 AI를 쓰지 않거나 믿기 어렵다고 했습니다.
   - (가) 김영균 HW6 버전의 세 가지를 그대로 씁니다. AI가 빠진 정보를 한두 개 더 묻고, 후보 카드 가운데 5～7장을 골라 "왜 지금인지"를 보호자의 답과 연결해 쓰고, 카드에 적힌 답을 상황에 맞춰 풀어 씁니다. 여기에 유정민 님의 "의료진에게 물어볼 질문으로 바꾸기"를 더합니다. **추천합니다.** 사실은 모두 확인한 카드에서 나오고, AI가 꺼지면 규칙 목록으로 돌아가며, 이미 만들어 돌려 본 코드가 있습니다.
   - (나) (가)에 더해 돌봄 방식 비교도 유정민 님 프로토타입처럼 AI가 씁니다. 상황에 더 잘 맞지만 비교 내용이 매번 달라져 검수가 어렵습니다.
   - (다) AI 없이 냅니다. 가장 안전하지만 과목 취지와 멀어집니다.
2. **응급 안내를 어떻게 둘까.** 첫 화면에서 묻는 방식은 이미 신고한 사람에게 같은 질문을 다시 하게 한다는 백민경 님의 지적이 맞다고 봅니다. 추천은 첫 화면에서는 묻지 않되, 자유 입력에 응급 신호가 있으면 바로 띄우고, 화면 아래에 "즉시 도움이 필요할 때"를 늘 두는 것입니다.
3. **처음에 다룰 상황을 몇 개로 할까.** 세 사람의 상황을 합치면 아홉 개입니다(치매 의심·등급 신청 전, 등급 직후, 입원·퇴원, 낙상, 증상 악화, 보호자 사정 변화, 이용 기관 문제, 시설 검토, 잘 모르겠어요). 추천은 인터뷰에서 재결정의 계기로 나온 낙상, 증상 악화, 입원·퇴원에 "잘 모르겠어요"를 더한 네 개로 시작하는 것입니다. 낙상과 증상 악화는 비교 카드와 할 일 카드가 이미 있고, 입원·퇴원은 할 일 카드만 있어 비교 카드를 새로 써야 합니다.
4. **제품 이름.** 새로 정합니다. 부모를 모시는 자녀만 떠올리게 하는 이름은 피합니다. 조부모나 배우자를 돌보는 보호자도 대상이기 때문입니다. 후보는 아래 다섯 개이고, 같은 이름의 서비스나 상표가 있는지는 아직 찾아보지 않았으므로 정하기 전에 확인합니다.

   | 후보 | 뜻 | 좋은 점 | 걸리는 점 |
   |---|---|---|---|
   | 돌봄수첩 | 할 일을 적어 두는 수첩 | 탭이 달린 수첩 모양의 화면과 맞고, 설명 없이도 무엇인지 압니다. 체크하고 다시 펴 보는 쓰임새도 담습니다. **추천합니다.** | 흔한 말이라 다른 서비스와 구별하기 어렵고, 돌봄 방식 비교는 드러나지 않습니다. |
   | 돌봄길잡이 | 돌봄의 길을 안내 | 뜻이 분명하고 연령대를 가리지 않습니다. | 공공기관 안내 책자 같은 인상을 주고, 결정을 대신해 준다고 읽힐 수 있습니다. |
   | 돌봄이정표 | 갈림길에서 방향과 다음 지점을 알려 주는 표지 | 돌봄 방식이 갈리는 지점과 다음 할 일을 함께 담습니다. 가리키기만 하고 결정은 보호자가 한다는 원칙과도 맞습니다. | 다섯 글자라 길고, 말로 부르기에는 조금 딱딱합니다. |
   | 돌봄한장 | 상황을 한 장으로 정리 | 인터뷰에서 고른 모양("할 일과 받을 지원을 한 장에 정리")을 그대로 담습니다. | 화면이 실제로는 탭과 여러 장으로 나뉘어 이름과 어긋날 수 있습니다. |
   | 돌봄나침반 | 방향을 잡아 주는 나침반 | 막막할 때 방향을 잡는다는 뜻이 바로 전해집니다. | 복지 분야에서 자주 쓰는 비유라 겹칠 가능성이 높습니다. |
5. **누가 무엇을 맡고 누가 검수할까.** 추천은 각자 자기 프로토타입에서 가장 잘 만든 부분을 맡고, 내용 검수는 옆 사람이 하는 것입니다. 백민경 님이 돌봄 방식, 유정민 님이 자료 목록과 AI 호출, 한수연 님이 질문과 답, 김영균이 뼈대와 할 일 카드를 맡는 식입니다.
6. **서버를 어디에 올릴까.** AI를 부르려면 API 키를 숨길 서버가 필요해, 정적 호스팅만으로는 올릴 수 없습니다. 보호자에게 링크로 보여 주려면 Node 서버를 올릴 곳과 API 비용을 누가 낼지를 정해야 합니다.

## 미리 알아 둘 위험

- **내용 검수가 가장 큰 일입니다.** 할 일 카드 43장과 답 55개는 김영균 혼자 확인했고, 백민경 님의 연락처는 "확인 전"입니다. 제도 정보가 틀리면 보호자에게 실제 손해가 생기므로, 상황 수를 줄여서라도 낸 내용은 모두 두 사람이 확인해야 합니다.
- **질문이 길어집니다.** 세 사람의 질문을 그대로 합치면 스무 개가 넘습니다. 병원 대기실에서 3분 안에 끝나도록 기본 정보와 상황별 질문을 합쳐 열 개 안쪽으로 줄여야 합니다.
- **AI가 고르는 카드는 돌릴 때마다 조금씩 다릅니다.** HW6 점검에서 같은 사례를 두 번 돌리자 막힌 일에 맞는 카드가 10장 중 10장, 9장으로 달랐고, 목록 하나에 6～8초가 걸렸습니다. 데모와 보호자 확인 전에 사례 점검을 여러 번 돌려 빠지는 카드를 확인해야 합니다.
- **보호자에게 직접 확인한 적이 없습니다.** 사례 점검은 인터뷰 요약과 만든 상황으로 돌린 것입니다. 12월 둘째 주 전에 실제 보호자 몇 분께 보여 드리는 일정을 잡아야 합니다.
- **제도가 바뀝니다.** 요양병원 간병비 급여화처럼 예고된 변화가 있어, 자료 목록에 확인한 날짜를 적고 화면에도 보여 줍니다.
