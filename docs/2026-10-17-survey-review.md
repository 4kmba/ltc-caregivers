# 보호자 설문 문항 검토 (2026-10-17)

대상: 「장기요양·가족돌봄 의사결정 경험 설문」(Apps Script 웹 설문, 12문항)
작성: 김영균

## 요약

- Q4·Q5·Q7·Q10은 보기가 8~10개라 휴대폰에서 한 화면을 넘는다. 보기끼리 겹치는 것이 많아 응답자가 "둘 중 뭘 고르지"에서 멈추기 쉽다.
- Q4를 **단일 선택**으로 바꾸면 Q5·Q7·Q10이 모두 "그 결정 하나"에 대한 질문이 되어 짧고 명확해진다.
- 보기 수를 줄이면 Q4 9→6, Q5 10→6, Q7 8→5, Q10 10→6이 된다.

## 1. 문항별 보기 수정안

### Q4. 가장 판단하기 어려웠던 결정 (9개 → 6개, 단일 선택)

질문을 "가장 판단하기 어려웠던 결정 **하나**를 골라주세요"로 바꾼다.

| 현재 보기 | 수정안 |
|---|---|
| 병원·치료·재활 관련 결정 | 병원·치료·재활 관련 결정 |
| 이용할 요양기관 선택 / 집에서 계속 돌볼지 시설을 이용할지 결정 | 집에서 돌볼지, 시설·요양기관에 맡길지 (두 보기 통합) |
| 장기요양서비스(방문요양·주야간보호 등) 선택 | 방문요양·주야간보호 등 장기요양서비스 선택 |
| 복지용구 구입·대여·설치 | 복지용구(보행기, 침대, 매트 등) 구입·대여 |
| 간병·돌봄 비용 결정 | 비용을 누가 얼마나 부담할지 |
| 가족 간 돌봄 역할 분담 | 가족 간 돌봄 역할 분담 |
| 상태 악화 후 기존 돌봄방식 변경 | 삭제 (결정의 종류가 아니라 시점이라 다른 보기와 겹침) |
| 기타 | 기타 (자유 입력란 추가) |

### Q5. 그 결정이 어려웠던 이유 (10개 → 6개, 최대 2개)

정보 부족, 정보가 흩어짐, 기관마다 설명이 다름, 장단점 비교 어려움이 모두 '정보 문제'의 변형이라 응답이 분산된다. 원인 유형별로 묶는다.

| 현재 보기 | 수정안 |
|---|---|
| 필요한 정보가 부족하거나 여러 곳에 흩어져 있어서 / 선택지별 장단점을 비교하기 어려워서 | 믿을 만한 정보가 부족하거나 흩어져 있어서 |
| 사람·기관마다 설명이나 의견이 달라서 | 기관·전문가·가족마다 말이 달라 누구 말을 따를지 몰라서 |
| 비용 부담 또는 비용 차이를 알기 어려워서 | 선택지마다 비용이 얼마나 드는지 알기 어려워서 |
| 가족 구성원들의 의견이 달라서 | 가족 간 의견이 달라서 |
| 심리적으로 지쳐 판단할 여유가 없어서 / 충분히 알아볼 시간이 부족해서 | 지치고 시간이 없어 알아볼 여유가 없어서 |
| 환자 상태가 계속 변해서 | 어르신 상태가 계속 변해서 |
| 특별히 어렵지 않았다 | 삭제 (Q4에서 어려웠던 결정을 이미 골랐으므로 나올 수 없는 답) |
| 기타 | 기타 |

"장단점 비교"는 우리 가설과 직결되지만 응답자 입장에서는 "정보 부족"과 구분되지 않는다. 비교에 대한 수요는 Q10에서 도움 유형으로 측정한다.

### Q7. 최종적으로 어떻게 결정했나 (8개 → 5개, 단일 선택)

"주 보호자가 판단했다"와 "실제로 돌봄을 하는 사람의 의견을 따랐다"는 대부분 같은 사람이고, "처음 상담한 기관"과 "가장 신뢰하는 전문가·기관"은 응답자가 구분하기 어렵다. 다만 "처음 상담한 기관이 권한 대로"는 가설(파는 쪽이 계획을 짠다)을 확인하는 핵심 보기이므로 따로 둔다.

| 현재 보기 | 수정안 |
|---|---|
| 처음 상담한 기관의 의견을 따랐다 | 처음 상담한 기관·업체가 권하는 대로 했다 |
| 내가 추가 정보를 찾아 판단했다 | 내가 직접 정보를 찾아 비교하고 정했다 |
| 가족끼리 논의해 결정했다 / 주 보호자가 판단했다 / 실제로 돌봄을 하는 사람의 의견을 따랐다 | 가족끼리 의논해 정했다 (세 보기 통합) |
| 가장 신뢰하는 전문가·기관의 의견을 따랐다 | 의사·사회복지사 등 따로 신뢰하는 사람의 조언을 따랐다 |
| 시간이 부족해 당시 가능한 선택을 바로 했다 | 시간이 없어 당장 가능한 선택을 했다 |
| 기타 | 기타 |

### Q10. 당시 가장 필요했던 도움 (10개 → 6개)

현재 보기는 사실상 기능 목록이라, 응답자가 자기 경험이 아니라 "있으면 좋을 것 같은 것"을 고를 위험이 있다. 비슷한 것끼리 묶고 응답자의 말로 바꾼다.

| 현재 보기 | 수정안 |
|---|---|
| 지금 무엇을 결정해야 하는지 정리 / 환자 상태를 객관적으로 정리 | 지금 무엇을 결정해야 하고 상황이 어떤지 정리해 주는 것 |
| 전문가·가족 의견을 한곳에 정리 / 서로 다른 의견이나 추가 확인이 필요한 부분 알려주기 | 여러 사람 말을 한데 모아 어디가 다른지 짚어 주는 것 |
| 가능한 돌봄방식과 장단점 비교 / 비용과 가족의 돌봄 부담 비교 | 선택지별 장단점과 비용을 나란히 비교해 주는 것 |
| 이용 가능한 공공지원·제도 안내 | 받을 수 있는 공공 지원·제도를 알려 주는 것 |
| 믿을 수 있는 전문가·기관 연결 | 믿을 만한 전문가나 기관을 연결해 주는 것 |
| 특별히 필요한 도움이 없었다 | 특별히 필요한 도움이 없었다 (다른 보기와 함께 선택 불가) |
| 기타 | 기타 |

선택 방식은 "1순위 하나를 먼저 고르고, 추가로 하나 더"로 나누면 분석할 때 가중치를 둘 수 있다.

## 2. 보기 외에 손봤으면 하는 것

1. **Q4·Q5·Q10 보기 순서를 무작위로 섞는다.** 보기가 많을수록 앞쪽 보기가 더 많이 선택되는 경향(초두 효과)이 있다. Apps Script에서 렌더링할 때 배열을 섞고, "기타"와 "없었다"만 맨 아래에 고정한다.
2. **Q6과 Q9가 거의 같은 질문이다.** Q6(전문가·기관·가족 의견 차이)이 Q9(가족 간 의견 차이)을 포함한다. 하나를 빼거나, Q6을 "전문가·기관 간 의견 차이"로 좁혀 역할을 나눈다.
3. **예상 소요시간 "2~3분"은 현재 구조로는 어렵다.** 보기가 총 70개 가까이라 4~5분은 걸린다. 보기를 줄인 뒤 팀원이 아닌 사람 3명에게 시켜 보고 실제 시간을 안내문에 적는다.
4. **휴대폰 화면에서 두 줄로 꺾이는 보기를 없앤다.** "집에서 계속 돌볼지 / 시설을 이용할지 결정", "장기요양서비스(방문요양·주야간보호 등) 선택"이 375px 폭에서 두 줄이 된다. 위 수정안대로 줄이면 대부분 한 줄에 들어온다.

확인 완료: "최대 2개" 제한은 코드로 막혀 있고, Q12에서 "참여 가능"을 고르면 연락처 입력란이 나온다.

## 3. 설문의 목적

이 설문은 돌봄 전반의 의사결정 페인포인트를 넓게 탐색하는 용도다. 복지용구는 Q4의 보기 하나로 들어가 있고, `PROJECT.md`의 중단 기준(사업소 제안을 두고 망설였는지)은 이 설문이 아니라 후속 인터뷰로 판정한다. 그래서 Q12의 후속 인터뷰 동의가 중요하고, Q4에서 복지용구를 고른 응답자를 인터뷰 대상으로 우선 연락한다.
