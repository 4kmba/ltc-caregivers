# 스펙: 돌봄 AI

- 작성자: 유정민
- 작성일: 2026-10-29
- 상태: 검토 중
- 기능: 보호자가 상황을 고르면 돌봄 방식 선택지를 한 장으로 정리해 주는 AI
- 정한 방법: grilling 세션에서 질문 11개에 답하며 정했다.

## 1. 누구를 위한 기능인가

부모나 조부모를 돌보며 돌봄 방식을 정해야 하는 가족 보호자를 위한 기능이다. 문제가 생기는 순간은 두 가지다.

- **돌봄을 처음 시작할 때.** 진단을 받았거나 장기요양등급을 막 받았는데, 어떤 서비스부터 써야 할지 모른다. 설문(`docs/2026-10-25-survey-results.md`)에서 당시 가장 필요했던 도움 1위가 "받을 수 있는 공공 지원·제도 안내"(17명 중 10명)였고, "지금 무엇을 결정해야 하는지 정리"(8명)가 뒤를 이었다.
- **상황이 바뀌었을 때.** 입원, 낙상, 증상 악화, 보호자 사정 변화, 이용하던 기관의 문제가 생겨 지금 돌봄 방식을 유지할지, 서비스를 늘릴지, 시설을 알아볼지 다시 정해야 한다. 후속 인터뷰에서 결정을 다시 내린 5명(C2, C5, C6, H1, C7)은 모두 입원, 낙상, 증상 악화가 계기였고, "다음 단계로 넘어갈 때를 모르겠다"고 말한 사람도 5명이었다(`docs/meetings/2026-10-28.md`).

설계할 때 지킬 조건도 인터뷰에서 나왔다. AI를 쓰지 않는 이유로 "내가 질문을 제대로 못 할 것 같다"는 말이 나왔다(`docs/meetings/2026-10-28-minutes.md`). 그래서 보호자는 질문을 만들지 않고 고르기만 해도 결과를 받는다. AI를 믿지 않거나 쓰지 않는 사람이 4명이었다(C5: "가짜 정보도 섞여 나와서 신뢰하기 어렵더라고요"). 그래서 지원과 연락처는 직접 확인한 공식 출처에서만 보여 준다.

설문은 카카오톡 방에서 모은 17명이고 인터뷰는 8명이라, 위 숫자를 보호자 전체의 비율로 읽지 않는다.

## 2. WhyTree의 어느 노드를 위한 기능인가

`docs/whytree/유정민.md`의 아래 경로를 따른다.

- 돌봄 ai (씨앗)
  - → 돌봄 방식 제안
    - → 돌봄 정보 제공
      - → 돌봄을 돕는 것

이 기능은 "돌봄 방식 제안" 노드를 위한 것이다. 보호자의 상황에 맞는 돌봄 방식을 2～3개로 정리해 제안하고, 받을 수 있는 지원과 연락처를 함께 보여 줘 위 노드인 "돌봄 정보 제공"으로 이어진다.

## 3. 무엇을 만드는가

브라우저에서 여는 웹 화면이다. 화면이 질문 7개를 차례로 묻고, 보호자가 고르기로 답하면 Claude가 돌봄 방식 제안을 한 장으로 정리해 보여 준다. 코드는 `prototypes/유정민/`에 두고, API 키가 브라우저로 가지 않도록 작은 서버가 Claude API를 부른다.

### 한 장에 담는 것

| 칸 | 내용 | 누가 쓰나 |
|---|---|---|
| 맨 위 문구 | "참고용 정리입니다. 결정은 가족과 의료진이 함께 하세요." | 화면에 고정 |
| 지금 결정할 것 | 한 줄 | AI |
| 돌봄 방식 비교 | 2～3개. 방식마다 장점, 단점, 비용 기준, 가족 부담 | AI |
| 받을 수 있는 지원과 연락할 곳 | 이름, 한 줄 설명, 링크, 전화번호 | AI가 자료 번호를 고르고, 화면이 자료 목록에서 꺼내 보여 줌 |
| 의료진에게 물어볼 질문 | 의료 판단이 필요한 내용이 나왔을 때만 | AI |

돌봄 방식은 비교만 하고 하나를 골라 주지 않는다. 비용은 금액을 계산하지 않고, 공식 자료에 적힌 본인부담률 같은 기준만 적는다.

### 공식 자료 목록

`prototypes/유정민/` 안의 파일 하나에 공식 자료 10～20개를 담는다. 항목마다 번호, 이름, 한두 줄 요약, 링크, 전화번호를 적는다. 출처는 국민건강보험공단 장기요양, 복지로, 치매안심센터, 보건소 같은 공공 기관으로 한정한다. 링크와 전화번호는 직접 열어 확인한 것만 넣고, 확인하지 못한 항목은 뺀다. 파일에 확인한 날짜를 적는다.

AI는 이 목록 안에서만 지원과 연락처를 고른다.

## 4. 사용자가 할 수 있는 일

1. 첫 화면에서 "지금 어르신이 응급 상황인가요?"에 답한다. "예"를 누르면 119와 진료받는 병원에 연락하라는 고정 안내만 보이고, 질문으로 넘어가지 않는다.
2. "아니오"를 누르면 아래 질문 1～5에 차례로 고르기로 답한다.
3. 마지막 질문 6에 더 알려 주고 싶은 것을 적거나, 비워 둔다.
4. "정리하기"를 누르고, "정리하는 중" 표시를 보며 기다린다.
5. 한 장을 읽는다. 지원 항목의 링크를 눌러 공식 원문을 열거나, 전화번호를 확인한다.
6. 정리하지 못했다는 안내가 나오면 다시 시도 버튼을 누르거나, 함께 나온 고정 안내의 연락처로 문의한다.

| 순서 | 질문 | 답 |
|---|---|---|
| 0 | 지금 어르신이 응급 상황인가요? | 예 / 아니오 |
| 1 | 어떤 상황인가요? | 돌봄을 처음 시작함 / 입원·퇴원 / 낙상 / 증상 악화 / 보호자 사정이 바뀜 / 이용하던 기관 문제 |
| 2 | 어르신 거동은 어떤가요? 치매 진단을 받았나요? | 혼자 걸음 / 부축 필요 / 주로 누워 지냄 · 진단 받음 / 의심됨 / 아님 |
| 3 | 장기요양등급이 있나요? | 없음 / 신청 중 / 1～5등급 / 인지지원등급 / 모름 |
| 4 | 지금은 어떻게 돌보고 있나요? (여러 개 선택) | 가족이 직접 / 방문요양 / 주간보호 / 요양원 / 요양병원·입원 중 |
| 5 | 가족이 돌봄에 낼 수 있는 시간과 비용 부담은? | 시간: 거의 없음 / 일부 / 대부분 · 비용 부담: 큼 / 보통 / 크지 않음 |
| 6 | 더 알려 주고 싶은 것 (선택) | 자유 입력 한 칸 |

등급 "없음"과 "모름"을 넣은 것은 등급 경계에 있어 지원을 받지 못하는 사람도 대상으로 보기 때문이다(`docs/meetings/2026-10-28-minutes.md`). 이름, 나이, 주소처럼 사람을 알아볼 수 있는 정보는 묻지 않는다.

응급 안내 문구는 공식 출처에서 확인한 내용만 쓰고, 그 출처를 자료 목록에 적는다.

## 5. 우선순위

### P0 (반드시 만든다)

- 응급 확인과 고정 응급 안내
- 질문 0～6. 고르기로 답하고, 6번만 선택 사항인 자유 입력
- 한 장 결과: 지금 결정할 것 한 줄, 돌봄 방식 2～3개 비교, 받을 수 있는 지원과 연락할 곳
- 공식 자료 목록 파일. AI는 자료 번호만 고르고, 화면이 목록에서 꺼내 보여 줌
- 맨 위 고정 문구와, 의료 질문을 "의료진에게 물어볼 질문"으로 바꾸기
- 실패 처리: "정리하지 못했어요" 문구, 다시 시도 버튼, 고정 안내, 목록에 없는 번호 버리기

### P1 (시간이 되면)

- 한 장 아래에서 이어 묻는 채팅
- 답을 고쳐 한 장 다시 만들기. 상황이 또 바뀌었을 때 처음부터 다시 답하지 않아도 된다
- 한 장을 복사해 가족에게 보내기. 설문에서 가장 어려웠던 결정으로 "가족 간 돌봄 역할 분담"을 고른 사람이 17명 중 9명이었다

### P2 (나중에)

- 음성 입력. 10/28 회의에서 2단계 기능으로 미뤘다
- 결과 저장과 상황 변화 기록
- 사는 지역에 맞춘 기관 목록

## 6. 범위 밖

1. **돌봄 방식 하나를 골라 주기.** 2～3개를 비교만 하고 결정은 보호자가 한다. `docs/PROJECT.md`의 "AI는 최종 결정을 대신하지 않는다"를 따른다.
2. **정확한 비용 금액 계산.** 등급, 이용 시간, 감경 여부에 따라 금액이 달라져 틀리게 말할 위험이 크다. 기준만 보여 준다.
3. **진단, 약, 치료 판단.** 의료진이 판단할 일이다. "의료진에게 물어볼 질문"으로 바꿔 보여 준다.
4. **특정 기관이나 요양보호사 추천과 평점.** 직접 고른 공식 자료로는 기관을 평가할 수 없고, 틀리면 특정 기관에 피해를 줄 수 있다. 연락처는 공단, 치매안심센터, 보건소 같은 공공 창구만 보여 준다.
5. **가족과 전문가 의견을 모아 다른 점 짚기.** 10/28 어젠다에서 근거가 가장 약한 가지였다. 여러 의견을 모아 정리하기 어려웠다는 사람이 2명이었고, 인터뷰에서 이 형태를 고른 사람은 없었다.
6. **보호자끼리 연결하는 커뮤니티나 매칭.** 10/28 회의에서 운영자가 통제하기 어렵고 사고 위험이 있어 보류했다.
7. **웹 검색으로 최신 정보 가져오기.** 블로그 같은 출처가 섞인다. 직접 고른 공식 자료 안에서만 답한다.
8. **로그인과 개인정보 저장.** 답은 브라우저를 닫으면 사라진다.

## 7. AI 모델과 실패 시 동작

### 모델

Claude Sonnet 5.5(`claude-sonnet-5-5`)를 쓰고, 한 장을 만들 때 요청을 한 번 보낸다. Claude Opus 5.5보다 비용이 절반이고 빠르며, 한국어 설명과 비교표를 만드는 데 충분하다.

AI에게는 보호자의 답과 공식 자료 목록(번호, 이름, 요약)을 준다. AI는 정해진 JSON 형식으로 답한다. 담는 것은 지금 결정할 것, 돌봄 방식 2～3개와 각각의 장점·단점·비용 기준·가족 부담, 지원 자료 번호, 의료진에게 물어볼 질문이다. 지원과 연락처는 글로 쓰지 않고 자료 번호만 고른다. 링크와 전화번호를 지어낼 수 없게 하려는 것이다.

진단, 약, 치료 여부처럼 의료진이 판단할 내용이 보호자의 답에 나오면, AI는 답하지 않고 "다음 진료 때 의료진에게 물어볼 질문"으로 바꿔 한 장에 넣는다.

### 실패 시 동작

| 상황 | 화면 |
|---|---|
| 응급 확인에서 "예" | AI를 부르지 않는다. 119와 진료받는 병원에 연락하라는 고정 안내만 보여 준다 |
| 응답이 없음 (네트워크·API 오류, 30초 초과) | "정리하지 못했어요" 문구, 다시 시도 버튼, 고정 안내 |
| 형식이 깨짐 (돌봄 방식이 2～3개가 아니거나 빈 칸이 있음) | 응답이 없을 때와 같다 |
| 자료 목록에 없는 번호를 고름 | 그 번호는 버리고 나머지만 보여 준다. 남은 항목이 없으면 고정 안내를 보여 준다 |

고정 안내에는 국민건강보험공단 장기요양(1577-1000), 지역 치매안심센터, 보건소를 넣는다. 번호와 링크는 자료 목록을 만들 때 확인한 것만 쓴다. AI가 답하는 동안에는 "정리하는 중" 표시를 보여 준다.

## 8. 손으로 하는 체크

완료 여부는 아래 세 가지를 직접 돌려 판정한다. AI 답은 매번 조금씩 다르므로 체크 2는 여러 번 돌린다.

1. **AI 없이도 안전 안내가 나온다.** 응급 확인에서 "예"를 누르면 질문으로 넘어가지 않고 응급 안내만 나온다. `.env`의 API 키를 비우고 끝까지 답하면, 오류로 멈추지 않고 다시 시도 버튼과 고정 안내가 나온다.
2. **한 장이 다 채워지고 출처가 진짜다.** "돌봄을 처음 시작함"과 "낙상" 두 상황을 각각 두 번씩, 모두 네 번 돌린다. 네 번 모두 지금 결정할 것 한 줄, 돌봄 방식 2～3개 비교, 지원과 연락처가 나온다. 한 장의 링크를 모두 눌러 공식 사이트가 열리고, 이름과 전화번호가 자료 목록 파일과 같다.
3. **의료 판단을 하지 않는다.** 질문 6에 "약을 끊어도 될까요?"라고 적으면, 답 대신 "의료진에게 물어볼 질문"으로 나온다. 한 장 맨 위에 고정 문구가 있다.
