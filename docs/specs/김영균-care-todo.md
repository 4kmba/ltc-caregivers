# 스펙: 맞춤 돌봄 할 일 목록 (care-todo)

- 작성: 김영균, 2026-10-29
- 상태: 초안. 토요일 팀 회의에서 다른 팀원의 스펙과 비교한 뒤 정합니다. HW6 개인 프로토타입은 이 스펙으로 김영균이 혼자 만듭니다(`prototypes/김영균/`).
- 출발점: [WhyTree 김영균](../whytree/김영균.md)의 "대상자 맞춤 할 일 목록"

## 한 줄 요약

보호자가 몇 가지 질문에 답하면, 지금 돌봄 단계와 상황에 맞는 할 일 5～7개를 "이번 주, 이번 달, 미리 알아둘 것"으로 나눠 보여 줍니다. 할 일마다 왜 지금 해야 하는지, 어디에 연락하는지, 그 일을 할 때 물어볼 질문이 붙고, 질문을 누르면 출처가 있는 답을 볼 수 있습니다.

## 누구를 위한 기능인가

**대상.** 부모나 배우자 같은 가족의 장기요양 돌봄을 맡거나 함께 결정하는 가족 보호자입니다. 화면은 일하는 40～50대 자녀와 조부모를 돌보는 20～30대 영케어러(C6)를 기준으로 만듭니다. 두 무리 모두 출퇴근길이나 병원 대기실에서 휴대폰으로 잠깐씩 봅니다.

**문제가 나타나는 순간.** 단계를 가리지 않고, 보호자가 "지금 무엇부터 해야 하지?" 하고 막히는 때입니다. 인터뷰에서 들은 순간은 다음과 같습니다.

- 기억력이 떨어지는데 치매인지, 검사와 등급 신청을 지금 해야 하는지 모를 때 (C3, H2)
- 입원, 낙상, 증상 악화로 지금까지의 돌봄을 다시 정해야 할 때 (C2, C5, C6, C7, H1)
- 집에서 계속 돌볼지 시설로 옮길지 고민할 때 (C6)

10/28 회의에서 정리한 막힌 지점 가운데 "다음 단계로 넘어갈 때를 모름"이 5명으로 가장 많았습니다. 백민경 님 인터뷰에서는 "내가 질문을 제대로 못 할 것 같아서" AI를 쓰지 않는다는 말이 나왔고, 팀은 AI가 먼저 물어보고 이끌어 주기만 해도 도움이 되겠다고 봤습니다. 이 기능은 보호자가 질문을 만들지 않아도 답만 고르면 할 일과 물어볼 질문을 받도록 설계했습니다.

## 어떤 WhyTree 노드를 돕는가

- **주 노드:** "무엇을 언제 결정할지 알기" 아래의 새 방법 "대상자 맞춤 할 일 목록". 이 노드는 "합리적인 결정 → 내 결정에 확신 갖기 → 죄책감 없이 나를 돌볼 시간 갖기"로 이어집니다.
- **점선으로 돕는 노드:**
  - "정확한 정보 얻기": 할 일과 답마다 공식 자료의 출처를 붙입니다.
  - "놓친 정보까지 말하기": 보호자가 생각하지 못한 질문을 할 일에 붙여 줍니다.
  - "흩어진 정보 모아 주기": 공단, 보건소, 치매안심센터, 법령에 흩어진 내용을 할 일 카드 한 묶음으로 모읍니다.

## 사용자가 하는 일

모바일 웹에서 링크를 열어 씁니다. 로그인은 없습니다.

1. **시작.** 첫 화면에서 "몇 가지만 답하시면 지금 할 일을 정리해 드려요. 3분쯤 걸려요."를 보고 시작을 누릅니다.
2. **고정 질문에 답하기.** 모두에게 같은 질문 8개를 하나씩 보여 줍니다. 대부분 고르기만 하면 되고, 모르면 "잘 모르겠어요"를 고를 수 있습니다. 보기 하나만 고르는 질문은 고른 답을 잠깐 보여 준 뒤 다음 질문으로 넘어가고, 화면 낭독기에는 새 질문 제목을 알립니다. 이전 질문으로 돌아가 답을 바꾸는 버튼은 늘 보입니다. 첫 질문의 답으로 돌봄 단계를 정합니다(아래 "고정 질문 초안").
3. **보충 질문에 답하기.** AI가 앞의 답에서 비어 있는 부분을 1～3개 더 묻습니다. 예를 들어 "최근 입원"을 고른 사람에게 "퇴원 날짜가 정해졌나요?"를 묻습니다. 보기를 고르거나 직접 적을 수 있고, 건너뛸 수 있습니다.
4. **할 일 목록 받기.** 할 일 5～7개를 세 구간으로 나눠 보여 줍니다.
   - 이번 주: 늦추면 손해가 생기거나 다음 일을 못 하는 것
   - 이번 달: 이번 주 일이 끝나면 이어서 할 것
   - 미리 알아둘 것: 지금 할 일은 아니지만 상태가 바뀌면 바로 필요한 것

   항목마다 할 일, 왜 지금 해야 하는지(보호자의 답과 연결한 한두 문장), 연락처, 출처, 물어볼 질문 1～2개가 붙습니다.

   목록 맨 위에는 "지금은 이 일부터 해 보세요"와 아직 하지 않은 첫 번째 할 일을 보여 줍니다. 세 구간을 같은 무게로 늘어놓으면 보호자가 우선순위를 다시 판단해야 하기 때문입니다. 이번 주 할 일을 모두 마치면 이 자리에 "이번 주에 필요한 일을 확인했어요"와 다음 구간의 첫 할 일을 보여 줍니다. 세 구간은 수첩의 인덱스 탭처럼 "이번 주", "이번 달", "알아두기" 탭으로 나누고, 한 번에 한 장만 보여 줍니다. 탭마다 "2/3 완료"처럼 몇 개를 끝냈는지 표시하고, 처음에는 남은 일이 있는 가장 이른 장을 열어 둡니다. 이번 주를 모두 마치면 이번 달 장이 열립니다.

   할 일은 처음에 행동 제목과 "왜 지금"만 보이고, 누르면 연락하기, 물어볼 질문, 출처 순서로 펼쳐집니다.
5. **질문을 눌러 답 보기.** 붙은 질문을 누르면 답이 펼쳐집니다. 답은 카드에 미리 적어 둔 내용을 보호자의 상황에 맞게 풀어 쓴 것이고, 아래에 출처가 붙습니다. 일반적인 의료 정보(예: 낙상 뒤 살펴볼 것)도 카드에 있으면 답하되, "진단과 치료는 주치의와 상의하세요"를 함께 보여 줍니다.
6. **한 일 체크하기.** 끝낸 할 일을 체크합니다. 체크 상태와 받은 목록, 목록을 만들 때 쓴 답은 그 휴대폰의 브라우저에만 저장됩니다. 링크를 다시 열면 지난 목록과 체크가 그대로 남아 있고, "처음부터 다시"를 누르면 지워집니다. 목록만 남기면 질문을 눌렀을 때 그 사람의 상황에 맞춰 답을 풀어 쓸 수 없어서 답도 함께 저장합니다.
7. **상황이 바뀌면 다시 받기.** 목록 아래의 "상황이 바뀌었어요"를 누르면 지난 답이 채워진 질문이 다시 열려, 바뀐 답만 고치면 됩니다. 새 목록에 예전에 끝낸 할 일이 다시 나오면 체크를 그대로 두고, "완료한 일 2개는 그대로 두었어요"처럼 알려 줍니다. 처음 나온 할 일에는 "새로 추가됨"을 붙여, 보호자가 두 목록을 비교하지 않아도 되게 합니다.

### 화면과 접근성

- 탭 아래 흰 종이 한 장에 할 일을 여백과 얇은 선으로 나눕니다. 지금 열린 탭만 강조색 띠와 테두리로 종이와 이어 붙이고, 나머지 탭은 같은 회색으로 둡니다. 완료는 체크박스와 탭의 완료 개수로만 보여 줍니다.
- 탭은 화면 낭독기에 탭 목록으로 알리고, 키보드 화살표로 옮겨 갈 수 있게 합니다.
- 색 대비는 WCAG AA를 지키고, 키보드 포커스가 보이고, 화면 낭독기로 쓸 수 있고, 누르는 곳은 44px 이상으로 만듭니다.
- 화면 위 "글자 크게" 버튼을 누르면 질문, 선택지, 버튼, 펼친 내용까지 모두 한 단계 커집니다. 이 설정도 브라우저에 저장합니다.
- 휴대폰이 어두운 화면으로 설정돼 있으면 어두운 색으로 보여 줍니다.
- 응급 안내는 빨간색에만 기대지 않고 "즉시 도움이 필요할 때"라는 제목을 붙입니다.

**응급 신호가 나오면.** 보충 질문의 답에 응급 신호(예: "불러도 대답이 없어요", "때리려고 해요", "죽고 싶다고 해요")가 있으면, 목록보다 먼저 119와 정신건강위기상담전화(1577-0199) 안내를 화면 맨 위에 띄웁니다. 죽음이나 자살을 말하는 답이면 자살예방상담전화(109)도 함께 보여 줍니다. 109는 2024년 1월부터 흩어져 있던 자살예방 상담번호를 하나로 묶은 번호입니다. 안내를 닫으면 목록을 볼 수 있습니다.

### 고정 질문 초안

문구는 시안을 만들면서 다듬습니다.

| 번호 | 묶음 | 질문 | 답 형식 |
|---|---|---|---|
| 1 | 단계 | 지금 어떤 상황이세요? | 하나 고르기: 기억력이나 행동이 걱정돼 알아보는 중 / 장기요양등급을 받은 지 얼마 안 됐어요 / 최근 입원·낙상·상태 악화가 있었어요 / 집에서 돌보기 어려워 시설을 생각 중이에요 / 잘 모르겠어요 |
| 2 | 대상자 상태 | 돌보는 분은 누구이고, 연세는 어떻게 되세요? | 관계(부모, 배우자, 조부모, 기타) + 나이대 |
| 3 | 대상자 상태 | 진단받은 병이 있나요? | 여러 개 고르기: 치매, 파킨슨, 뇌졸중, 골절·낙상, 기타, 없음, 잘 모름 |
| 4 | 대상자 상태 | 혼자 할 수 있는 일은 어느 정도인가요? | 거동(혼자 걸음 / 부축 필요 / 주로 누워 지냄) + 대화(평소처럼 / 가끔 엉뚱함 / 어려움) |
| 5 | 제도·서비스 | 장기요양등급이 있나요? | 없음 / 신청 중 / 1～5등급 / 인지지원등급 / 잘 모름 |
| 6 | 제도·서비스 | 지금 받고 있는 돌봄은 무엇인가요? | 여러 개 고르기: 가족만 / 방문요양 / 주야간보호 / 요양원 / 요양병원·병원 입원 / 개인 간병인 / 기타 |
| 7 | 보호자 여건 | 보호자님의 사정을 알려 주세요. | 함께 사는지 / 일을 하는지 / 하루에 직접 돌볼 수 있는 시간(거의 없음, 2시간 이하, 반나절, 하루 종일) |
| 8 | 비용과 가족 | 한 달 돌봄에 쓸 수 있는 돈과, 가족끼리 나누는 방식은요? | 금액 구간 + 분담(정해져 있음 / 의논 중 / 혼자 부담 / 해당 없음) |

이름, 연락처, 주소, 주민번호는 묻지 않습니다.

### 할 일 카드

팀이 공단, 법제처, 보건소, 치매안심센터의 공개 자료로 카드를 미리 만듭니다. P0에서는 네 단계(① 치매 의심·등급 신청 전 ② 등급 직후 첫 서비스 ③ 입원·낙상·악화 뒤 다시 정하기 ④ 시설 입소 검토)마다 8～12장, 모두 30～50장을 목표로 합니다.

카드 하나에는 다음을 적습니다.

| 칸 | 내용 |
|---|---|
| 단계 | ①～④ 가운데 해당하는 것(여럿 가능) |
| 맞는 조건 | 고정 질문의 어떤 답일 때 후보가 되는지 (예: 5번이 "없음"이고 3번에 "치매") |
| 할 일 | 한 줄 (예: "치매안심센터에 조기검진 예약하기") |
| 기본 시점 | 이번 주 / 이번 달 / 미리 알아둘 것 |
| 왜 필요한가 | 두세 문장 |
| 연락처 | 기관 이름과 대표 번호 또는 찾는 방법 |
| 질문과 답 | 질문 1～2개와 각각의 답, 답의 출처 |
| 출처 | 문서 이름, 링크, 확인한 날짜 |

카드 내용과 출처는 만든 사람이 아닌 팀원 한 명이 다시 확인합니다. 다만 HW6 개인 프로토타입에서는 김영균이 혼자 카드를 쓰고, 제출 전에 공단 누리집, 국가법령정보센터, 중앙치매센터 같은 공식 자료를 웹에서 찾아 직접 확인합니다. 확인한 출처에는 확인한 날짜를 적고, 확인하지 못한 출처는 화면에 "출처 확인 전"으로 표시합니다. 팀원 검토는 팀이 이 기능을 쓰기로 정한 뒤에 합니다.

## AI 모델과 하는 일

**모델:** Claude Sonnet 5.5 (`claude-sonnet-5-5`). API 키는 환경 변수로 읽고, `.env.example`에는 변수 이름만 적습니다.

AI가 하는 일은 세 가지이고, 모두 팀이 만든 카드 안에서만 움직입니다.

1. **보충 질문 만들기.** 고정 질문의 답을 보고 빠진 정보를 묻는 질문 1～3개를 만듭니다.
2. **카드 고르고 설명 붙이기.** 코드가 먼저 단계와 조건으로 후보 카드를 거르고, AI는 그 후보 가운데 5～7장을 골라 구간을 정하고 "왜 지금인지"를 보호자의 답과 연결해 씁니다. 응답은 카드 ID가 들어간 정해진 JSON 형식으로 받습니다.
3. **질문에 답하기.** 보호자가 누른 질문의 답을, 카드에 적힌 답을 바탕으로 그 사람의 상황에 맞게 3～5문장으로 풀어 씁니다. 카드에 없는 내용은 덧붙이지 않고, 보호자가 적은 증상을 보고 얼마나 위급한지나 언제 병원에 가야 하는지는 판단하지 않도록 지시합니다. 응급 신호가 있었던 사람에게는 AI 답 위에 "위급할 수 있는 상황이면 먼저 119에 전화하세요"를 고정 문구로 붙입니다.

보호자의 답은 서버에 저장하지 않고, AI를 부를 때만 함께 보냅니다.

**거절되면 다른 모델로 한 번 더.** 돌봄 질문에는 폭력, 자살, 약 같은 말이 자주 나와서 안전 분류기가 정상적인 요청을 거절할 수 있습니다. 그래서 API의 서버 측 대체 기능(`fallbacks: "default"`)을 켜 둡니다. 거절되면 API가 같은 요청을 다른 모델로 다시 보내고, 그래도 거절되면 아래 "AI가 실패하면"의 동작을 따릅니다.

**만드는 방법.** Node 서버가 화면 파일을 내보내고, API 키를 서버에만 두고 Claude를 부릅니다. Claude는 공식 SDK(`@anthropic-ai/sdk`)로 부르고, 15초 안에 답하도록 생각 단계를 끄고(`thinking: between_tools`) 노력 수준을 낮춥니다(`effort: low`). 카드 고르기와 보충 질문은 JSON 형식을 지정해 받고, 카드 ID는 후보 목록 안에서만 고를 수 있게 합니다.

## 손으로 하는 점검

1. **인터뷰 사례로 돌려 보기.** 인터뷰 요약 5건(C2, C3, C5, C6, H1)의 상황을 비식별한 채로 고정 질문에 입력합니다. 단계가 맞게 잡히는지, 모든 할 일에 출처가 붙는지, 그 사람이 인터뷰에서 막혔다고 말한 일이 목록에 들어 있는지 확인합니다.
2. **AI 없이 돌려 보기.** API 키를 빼고 실행해, 규칙 기본 목록과 "AI 설명 없이" 안내, 공단 상담 번호가 나오는지 확인합니다.
3. **응급 신호 넣어 보기.** 보충 질문의 답에 "어제부터 불러도 대답이 없어요"를 넣고, 119 안내가 목록보다 먼저 뜨는지 확인합니다.
4. **다시 받기와 큰 글씨.** 할 일 두 개를 체크한 뒤 "상황이 바뀌었어요"로 답 하나를 바꿔 다시 받고, 체크가 유지됐다는 안내와 "새로 추가됨"이 보이는지 확인합니다. 글자 크게를 켜고 휴대폰 너비(375px)에서 글자가 잘리거나 가로로 넘치는 곳이 없는지 봅니다.
