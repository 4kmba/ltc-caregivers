## 1. 한 줄 요약

보호자가 상황을 고르고 몇 가지에 답하면, 고를 수 있는 돌봄 방법 2～3개를 비교하고, 그날 적은 내용을 날짜가 찍힌 기록 한 장으로 받습니다. 기록에는 답 요약, 고른 돌봄 방법, 가장 먼저 살펴볼 제안 하나, 이날 읽은 질문과 답이 남습니다. 상황이 바뀌면 바뀐 답만 고쳐 새 기록을 받고, 지난 기록은 첫 화면의 "지난 기록"에서 다시 봅니다. 모든 기록은 보호자의 휴대폰에만 저장됩니다.

## 2. 누구를 위한 기능인가

**대상.** 부모, 배우자, 조부모의 장기요양 돌봄을 맡거나 함께 결정하는 가족 보호자입니다. 일하는 40～50대 자녀와 20～30대 영케어러가 출퇴근길이나 병원 대기실에서 휴대폰으로 잠깐씩 보는 상황을 기준으로 만듭니다.

**문제가 나타나는 순간.** 어르신이나 가족의 상황이 바뀌어 지금까지의 돌봄을 다시 정해야 할 때입니다. 인터뷰에서 결정을 다시 내린 사람들의 계기는 주로 입원, 낙상, 증상 악화였습니다. 이때 보호자는 어떤 선택지가 있는지와 무엇부터 해야 하는지를 한꺼번에 알아내야 하고, 정보는 공단, 병원, 기관, 커뮤니티에 흩어져 있습니다.

**근거.**

- 인터뷰 9명 중 5명이 "다음 단계로 넘어갈 때를 모르겠다"고 했고, 4명이 정보가 흩어져 있어 내 상황에 맞는 답을 얻기 어렵다고 했습니다([인터뷰 집계](../interviews/2026-10-31-caregiver-aggregate.md)).
- 설문 17명이 고른 가장 필요했던 도움은 공공 지원·제도 안내(10명), 지금 무엇을 결정해야 하는지 정리(8명), 선택지별 장단점과 비용 비교(6명) 순이었습니다.
- 인터뷰한 9명 중 4명은 AI를 쓰지 않거나 믿기 어렵다고 했고, "내가 질문을 제대로 못 할 것 같다"는 말이 나왔습니다. 그래서 보호자는 고르기만 해도 결과를 받고, AI는 팀이 확인한 카드 안에서만 고르고 풀어 씁니다.

설문은 카카오톡 방에서 모은 17명이고 인터뷰는 그중 9명이라, 이 숫자를 보호자 전체의 비율로 읽지 않습니다.

## 3. 사용자가 하는 일

모바일 웹에서 링크를 열어 씁니다. 로그인은 없습니다.

1. **첫 화면에서 시작합니다.** 첫 화면에는 "우리 상황에 맞는 제안 받기", "궁금한 것 찾아보기", 날짜순 "지난 기록"이 있습니다. 처음 온 사람에게는 지난 기록 대신 "기록은 이 휴대폰에만 남아요"를 보여 줍니다. 수첩 위에는 돌보는 대상을 관계로만 적는 칸(예: "어머니 돌봄 기록")을 둘 수 있고, 이름은 적지 않게 안내합니다.
2. **상황을 고릅니다.** "우리 상황에 맞는 제안 받기"를 누르면 상황 카드 가운데 하나를 고릅니다(4절).
3. **기본 정보를 적습니다.** 등급, 받는 돌봄, 어르신 상태, 보호자 여건을 고르기로 답합니다. 모든 질문에 "잘 모르겠어요"가 있습니다. 처음에는 다섯 화면을 모두 묻고, 다음부터는 잘 바뀌지 않는 칸과 자주 바뀌는 칸을 나눠 묻습니다(4절).
4. **상황별 질문에 답합니다.** 고른 상황에 따라 미리 정해 둔 질문이 3개까지 나옵니다. 그래도 비어 있는 정보가 있으면 AI가 한두 개를 더 묻습니다. 보기를 고르거나 직접 적을 수 있고, 건너뛸 수 있습니다. 마지막에 요즘 가장 걱정되는 일을 한 줄로 적거나 비워 둡니다.
5. **돌봄 방법을 비교합니다.** 선택지가 갈리는 상황이면 돌봄 방법 카드 2～3개가 나옵니다. 카드마다 한 줄 요약, 장점, 단점, 비용 기준, 가족 부담, 바로 시작할 수 있는지가 같은 순서로 적혀 있습니다. 답과 가장 잘 맞는 카드 한 장에 "우리 상황과 잘 맞을 수 있음"과 그 이유 한 줄이 붙습니다. 점수가 같은 카드가 둘 이상이거나 맞는 답이 없으면 표시하지 않습니다. 건너뛴 질문은 "건너뛴 질문이 n개 있어요"로 아래에 알립니다.
6. **방법을 고르거나 건너뜁니다.** 카드 하나를 고르면 그 방법에 맞는 기록으로 넘어갑니다. "방법은 나중에 정할게요"를 누르면 어느 방법을 고르든 필요한 제안만 담깁니다. 선택지가 갈리지 않는 상황은 5, 6단계 없이 바로 7단계로 갑니다.
7. **기록을 받습니다.** 그날 날짜와 고른 상황이 제목이 되는 기록 한 장이 나옵니다. 제안(할 일 카드) 목록을 펼쳐 놓지 않고 아래 순서로 보여 줍니다.
   - **오늘 적은 내용.** 이번 상황별 질문과 보충 질문의 답, 걱정 한 줄을 두세 줄로 돌려줍니다. AI가 쓰고, AI가 실패하면 그 답을 그대로 나열합니다. 기본 정보는 여기 넣지 않고 날짜 아래에 "3등급 · 방문요양 · 치매 · 부축 필요"처럼 한 줄로 보여 줍니다.
   - **지난번과 달라진 것.** 두 번째 기록부터 지난 기록과 비교해 바뀐 답만 보여 줍니다(예: "병원 진료: 아직 → 진료 후 집으로").
   - **고른 돌봄 방법.** 5, 6단계에서 고른 돌봄 방법이나 "아직 정하지 않았어요"입니다.
   - **가장 먼저 살펴볼 제안.** 제안 하나만 노랑 카드로 보여 줍니다. 누르면 "지금 하면 좋은 이유", 연락할 곳, 물어볼 질문, 출처가 펼쳐집니다. "지금 하면 좋은 이유"는 AI가 보호자의 답과 연결해 한두 문장으로 씁니다.
   - **더 살펴볼 제안.** 나머지 제안 4～6개는 접어 두고, 펼치면 "이번 주, 이번 달, 알아두기"로 묶어 보여 줍니다.
   - **이런 일이 생기면 다시 제안을 받아 보세요.** 지켜볼 신호 2～3개입니다.
8. **질문을 눌러 답을 봅니다.** 제안에 붙은 질문을 누르면 답이 펼쳐집니다. 답은 카드에 미리 적어 둔 내용을 AI가 보호자의 상황에 맞게 3～5문장으로 풀어 쓴 것이고, 아래에 출처가 붙습니다. 의료 판단이 필요한 질문은 답 대신 "다음 진료 때 의료진에게 물어볼 질문"으로 보여 줍니다. 열어 본 질문과 그때 본 답은 기록의 "이날 읽은 질문"에 그대로 저장되어, 나중에 다시 열어도 같은 글이 나옵니다.
9. **원하면 체크합니다.** 제안 체크는 선택입니다. 체크하지 않아도 기록은 그대로 남습니다. 지난 기록과 표지 날짜 탭에는 남은 제안 개수를 적지 않습니다. "남은 일 n개"가 숙제처럼 읽힌다는 의견을 받아 뺐습니다([문구 원칙](../ux-writing.md) 7).
10. **지난 기록을 다시 봅니다.** 첫 화면의 "지난 기록"은 날짜, 상황, 고른 돌봄 방법을 한 줄씩 보여 줍니다. 누르면 그날 기록이 저장된 그대로 열립니다.
11. **상황이 바뀌면 새 기록을 받습니다.** 기록 아래 "상황이 바뀌었어요"를 누르면 그 기록의 답이 채워진 질문이 열리고, 바뀐 답만 고치면 됩니다. 새 날짜의 기록이 하나 더 생기고 지난 기록은 고치지 않고 남깁니다. 예전에 끝낸 제안이 새 기록에 다시 나오면 체크를 그대로 두고, 처음 나온 제안에는 "새로 추가됨"을 붙입니다.
12. **카톡으로 보낼 글을 복사합니다.** 기록마다 "카톡으로 보낼 글 복사"가 있습니다. 날짜, 상황, 오늘 적은 내용, 고른 돌봄 방법, 가장 먼저 살펴볼 제안, 연락할 곳을 붙여 넣기 좋은 글로 만들어 휴대폰 클립보드에 복사만 합니다. 어디로 보낼지는 보호자가 정하고, 앱이 직접 보내지 않습니다. 가족과 나눠 보는 길이면서 기록을 따로 남겨 두는 방법이기도 합니다.
13. **주제별로 찾아봅니다.** "궁금한 것 찾아보기"에서 주제 다섯 개(등급 신청과 소견서, 비용과 지원, 기관 고르기, 증상과 약, 보호자 자신 돌보기)를 골라 질문과 답을 봅니다. 상황을 고르지 않아도 첫 화면에서 바로 들어갈 수 있습니다.
14. **기록을 지웁니다.** 기록마다 "이 기록 지우기"가 있고, 설정에 "모든 기록 지우기"가 있습니다. 지우면 그 휴대폰에 저장된 답, 기록, 체크가 사라지고 되살릴 수 없습니다.

## 4. 질문

세 프로토타입의 질문을 그대로 합치면 스무 개가 넘습니다. 카드를 고르는 데 실제로 쓰이는 항목만 남겨, 상황 1개, 기본 정보 5화면, 상황별 질문 최대 3개, AI 보충 질문 최대 2개, 걱정 한 줄로 줄입니다. 김영균 프로토타입에서 나이, 한 달 예산, 분담 방법은 카드 43장 가운데 한 장씩만 조건으로 썼고 관계는 쓰지 않았기 때문에 뺐습니다.

### 상황 카드

| 상황 | 비교 화면 | P0 | 출발 내용 |
|---|---|---|---|
| 갑자기 넘어지셨어요 (낙상) | 있음 | 예 | 백민경 방식 3개, 김영균 카드 |
| 증상이 나빠졌어요 (치매 증상 악화 등) | 있음 | 예 | 백민경 방식 3개, 김영균 카드 |
| 입원했거나 곧 퇴원해요 | 있음 | 예 | 김영균 카드. 방법 카드는 새로 씀 |
| 잘 모르겠어요 | 없음 | 예 | 백민경 공통 기본 플랜, 김영균 카드 |
| 주 보호자가 돌볼 수 없게 됐어요 | 있음 | 예 | 백민경 방식 3개, 김영균 카드 |
| 기억력이나 행동이 걱정돼 알아보는 중이에요 | 없음 | 예 | 김영균 카드 13장 |
| 등급을 받은 지 얼마 안 됐어요 | 없음 | 예 | 김영균 카드 22장 |
| 시설을 생각 중이에요 | 있음 | P1 | 김영균 카드 17장 |
| 이용하던 기관에 문제가 생겼어요 | 미정 | P2 | 내용 없음 |

김영균 카드는 상황이 아니라 돌봄 단계 네 개로 나뉘어 있습니다. 낙상, 증상 악화, 입원·퇴원은 모두 "입원·낙상·악화 뒤 다시 정하기" 단계의 카드 32장에서 나오므로, 카드마다 맞는 상황을 다시 표시합니다. 카드 수는 정적 버전(45장) 기준입니다. 검수(5절)를 마치지 못한 상황은 화면에 내지 않습니다.

### 기본 정보 (한 번 적고 저장)

| 화면 | 묻는 것 | 답 |
|---|---|---|
| 1 | 장기요양등급 | 없음 / 신청 중 / 1～5등급 / 인지지원등급 / 잘 모르겠어요 |
| 2 | 지금 받는 돌봄 (여러 개) | 가족만 / 방문요양 / 주야간보호 / 요양원 / 요양병원·병원 입원 / 개인 간병인 |
| 3 | 진단받은 병 (여러 개) | 치매 / 파킨슨 / 뇌졸중 / 골절·낙상 / 기타 / 없음 / 잘 모르겠어요 |
| 4 | 거동과 대화 | 혼자 걸음 / 부축 필요 / 주로 누워 지냄, 평소처럼 / 가끔 엉뚱함 / 어려움 |
| 5 | 보호자 여건 | 함께 사는지, 일을 하는지, 평일 낮에 곁에 있을 가족이 있는지, 비용 부담(큼 / 보통 / 크지 않음) |

이름, 연락처, 주소, 주민번호는 묻지 않습니다.

**두 번째부터는 바뀌는 칸만 다시 묻습니다.** 등급이나 진단은 한 번 정해지면 잘 바뀌지 않지만, 받는 돌봄과 거동·대화는 낙상이나 입원 뒤에 자주 바뀝니다. 그래서 칸을 둘로 나눠 묻습니다.

| 칸 | 묻는 방법 |
|---|---|
| 잘 바뀌지 않는 칸: 등급, 진단, 보호자 여건 | 지난 답을 요약 카드 한 장에 한두 줄로 보여 주고 "그대로예요"와 "고칠 게 있어요"를 고르게 합니다. "고칠 게 있어요"를 누르면 그 자리에서 보기를 펼칩니다 |
| 자주 바뀌는 칸: 받는 돌봄, 거동과 대화 | 화면 2와 4를 지난 답이 골라진 채로 다시 묻습니다. 그대로면 "다음"만 누릅니다 |

등급이 "없음"이나 "신청 중"이었으면 신청 결과가 나왔을 수 있으므로 화면 1을 다시 묻습니다. 지난 답에 빠진 칸이 있으면 그 칸이 든 화면은 처음처럼 묻습니다.

### 상황별 질문

| 상황 | 질문 |
|---|---|
| 낙상 | 병원 진료를 받았나요? (입원했다 / 진료 후 집으로 왔다 / 아직 받지 않았다) |
| 증상 악화 | 어떤 변화가 가장 큰가요? (기억 / 성격·행동 / 일상생활) · 혼자 있을 때 위험했던 일이 있었나요? · 최근 며칠이나 몇 주 사이에 갑자기 달라졌나요? |
| 입원·퇴원 | 병원에는 앞으로 얼마나 더 계실 것 같나요? (곧 퇴원 / 계속 계실 예정 / 아직 몰라요) |
| 주 보호자가 돌볼 수 없게 됨 | 카드를 상황별로 나누면서 정합니다. 백민경 프로토타입의 꼬리 질문에서 출발합니다 |
| 등급 직후, 걱정돼 알아보는 중 | 카드를 상황별로 나누면서 정합니다. 김영균 정적 버전의 보충 질문에서 출발합니다 |
| 방문요양이나 주야간보호를 쓰는 중이면 | 지금 받는 서비스는 어떠세요? (괜찮아요 / 바꾸고 싶어요 / 잘 모르겠어요) |
| 모두 | AI가 만드는 보충 질문 최대 2개 (7절) |
| 모두 | 요즘 가장 걱정되는 일 (한 줄, 비워도 됨) |

## 5. 내용 파일

내용은 다섯 파일에 두고 화면은 읽기만 합니다. 팀원이 코드를 건드리지 않고 내용만 고쳐 PR을 올릴 수 있게 하려는 것입니다.

| 파일 | 한 항목에 담는 것 |
|---|---|
| 상황과 질문 | 상황 번호, 제목, 한 줄 설명, 비교 화면 여부, 상황별 질문과 답 |
| 돌봄 방법 | 상황 번호, 제목, 한 줄 요약, 장점, 단점, 비용 기준(공식 자료의 본인부담률 같은 기준만), 가족 부담, 바로 시작할 수 있는지, 점수 규칙과 이유 문장, 먼저 넣을 제안 카드 번호, 뺄 카드 번호, 지켜볼 신호 |
| 제안 카드 | 상황, 조건(모두 맞아야 함 / 하나라도 맞으면 뺌 / 묶음 중 하나만 맞으면 됨), 제안 한 줄, 기본 구간, 왜 필요한가, 연락할 곳의 자료 번호, 붙는 질문 번호 |
| 질문과 답 | 질문, 답, 주제(다섯 개 중 하나), 자료 번호, 의료 주제 여부 |
| 자료 목록 | 번호, 이름, 기관, 링크, 전화번호, 한두 줄 요약, 확인한 날짜, 확인한 사람 두 명 |

**연락처와 링크는 자료 목록에만 적습니다.** 카드와 답은 자료 번호만 가리키고, 화면이 자료 목록에서 이름, 링크, 전화번호를 꺼내 보여 줍니다. 같은 번호가 여러 파일에 따로 적혀 서로 달라지는 일을 막기 위해서입니다. 김영균 카드의 연락처 문장과 출처 20개, 백민경 연락처 5곳, 유정민 자료 20개를 이 목록 하나로 합칩니다.

**확인하지 않은 내용은 화면에 내지 않습니다.** 자료 항목은 쓴 사람과 다른 팀원 한 명이 공식 사이트를 직접 열어 확인하고 날짜를 적습니다. 제안 카드와 질문·답은 유정민, 백민경, 한수연이 상황별로 나눠 검수하고, 누가 어느 상황을 맡을지는 세 사람이 정합니다. 확인한 사람이 둘이 안 되는 자료를 가리키는 카드와 답은 화면에 나오지 않고, 자동 점검이 그 수를 알려 줍니다.

## 6. 고르는 규칙

코드가 조건으로 후보를 거르고, AI가 그 안에서 고릅니다. AI가 실패하면 코드만으로 고릅니다. 김영균 프로토타입의 규칙(`prototypes/김영균/src/rules.mjs`)에서 출발합니다.

**돌봄 방법.** AI를 쓰지 않습니다. 방법마다 적어 둔 점수 규칙을 답과 맞춰 점수가 높은 순으로 놓고, 1등이 하나뿐이면 "잘 맞을 수 있음"과 이유 한 줄을 붙입니다.

**제안 후보 거르기(코드).** 상황과 조건이 맞는 카드를 후보로 두고, 고른 돌봄 방법이 빼라고 한 카드는 뺍니다. 고른 돌봄 방법이 가리키는 카드에는 "먼저" 표시를 붙여 AI에게 넘깁니다. 방법이 가리키는 카드라도 상황과 조건이 맞지 않으면 후보에 넣지 않고, "먼저" 표시도 붙이지 않습니다. 조건은 그 사람에게 해당하지 않는 일을 거르려고 둔 것이기 때문입니다. 예를 들어 "다른 가족과 교대 일정 짜기"는 "회사에 가족돌봄휴가나 휴직을 쓸 수 있는지 확인하기"를 먼저 하라고 가리키지만, 일하지 않는 보호자에게는 맞지 않는 일입니다. 가리킨 카드가 모두 빠지면 "먼저" 카드 없이 목록을 만듭니다.

**제안 고르기(AI).** 후보 가운데 5～7장을 골라 구간을 정하고 "지금 하면 좋은 이유"를 씁니다(7절).

**규칙 기본 목록(AI가 실패했을 때).** "먼저" 표시가 붙은 카드를 넣고, 세 구간이 비지 않게 하나씩 넣은 뒤, 조건이 많은 카드부터, 같으면 우선순위가 높은 카드부터 채워 6장 안팎을 만듭니다. 조건 수는 꼭 맞아야 하는 조건(`when`)만 셉니다. 맞으면 더 어울린다는 표시(`boost`)는 세지 않습니다. 후보가 3장보다 적어지는 경우는 지금 카드로는 없습니다. 상황마다 답을 고르게 뽑은 조합 2만 개를 넣어 확인했고(실제 보호자의 답 분포는 아님), 카드를 빼거나 조건을 고치면 다시 확인합니다. "왜 지금"에는 카드에 적어 둔 "왜 필요한가"를 그대로 보여 줍니다.

백민경 프로토타입의 "오늘 할 일"은 구간을 따로 만들지 않고 "이번 주"의 맨 앞 카드로 옮깁니다. 맨 위의 "가장 먼저 살펴볼 제안"이 오늘 할 일의 자리를 맡습니다.

## 7. AI가 하는 일과 실패했을 때

11/25 회의에서 기획안의 추천안 (가)로 정했습니다. 김영균 HW6 버전의 세 가지에 유정민 님의 의료 질문 바꾸기를 더한 것입니다. 돌봄 방법 비교는 AI가 쓰지 않습니다.

**원칙.** AI는 팀이 확인한 카드 안에서만 움직입니다. 카드 번호는 코드가 거른 후보 안에서만 고를 수 있고, 답은 카드에 적힌 내용만 풀어 씁니다. 연락처와 링크는 AI가 쓰지 않고 화면이 자료 목록에서 꺼냅니다. AI가 꺼져도 3절의 모든 단계가 규칙과 카드 원문만으로 돌아갑니다.

**AI가 하는 일.**

| 하는 일 | 언제 | AI가 내는 것 |
|---|---|---|
| 보충 질문 만들기 | 상황별 질문에 답한 뒤 | 답에서 비어 있는 정보를 묻는 질문 최대 2개와 보기 |
| 카드 고르고 이유 쓰기 | 기록을 만들 때 | 후보 카드 번호 5～7개, 카드마다 구간과 "지금 하면 좋은 이유" 한두 문장. 걱정 칸의 글과 보충 질문의 답을 함께 봅니다 |
| 질문에 답하기 | 보호자가 질문을 눌렀을 때 | 카드에 적힌 답을 그 사람의 상황에 맞춰 3～5문장으로 풀어 쓴 글 |
| 오늘 적은 내용 쓰기 | 기록을 만들 때 | 상황별 질문의 답, 보충 질문의 답, 걱정 한 줄을 두세 문장으로 돌려준 글. 기본 정보는 넣지 않습니다. 판단이나 권유는 넣지 않습니다 |
| 의료 질문 바꾸기 | 기록을 만들 때 | 걱정 칸에 진단, 약, 치료 판단을 묻는 말이 있으면 "다음 진료 때 의료진에게 물어볼 질문" 한두 문장. 답은 쓰지 않습니다 |

AI에게는 이렇게 지시합니다. 카드에 없는 제도, 금액, 연락처를 덧붙이지 않습니다. 보호자가 적은 증상을 보고 얼마나 위급한지나 언제 병원에 가야 하는지를 판단하지 않습니다. HW6 점검에서 "어제부터 불러도 대답이 없어요"에 AI가 119 대신 "가능한 한 빨리 진료를 받으라"고 답한 적이 있어 넣은 지시입니다. 응급 신호가 있었던 사람에게는 AI 답 위에 "위급할 수 있으면 먼저 119에 전화하세요"를 고정 문구로 붙입니다.

**보내는 것과 알리는 것.** AI에게는 이번에 고른 답, 보충 질문의 답, 걱정 한 줄, 후보 카드의 내용만 보냅니다. 지난 기록, 체크, 돌보는 대상 칸은 보내지 않습니다(8절 온디바이스 원칙). 서버는 받은 내용을 저장하지 않고 AI를 부를 때만 넘깁니다. 첫 화면과 직접 적는 칸 아래에 "이름, 주소, 연락처는 적지 마세요. 답하신 내용은 제안을 고르는 데만 AI에 보내요."를 적습니다.

**모델.** Claude Sonnet 5.5(`claude-sonnet-5-5`)를 공식 SDK로 부릅니다. API 키는 서버의 환경 변수에서만 읽고 `.env.example`에는 변수 이름만 적습니다. 15초 안에 답하도록 노력 수준을 낮추고, 보충 질문과 카드 고르기는 JSON 형식을 지정해 받습니다. 돌봄 질문에는 폭력, 자살, 약 같은 말이 자주 나와 정상적인 요청이 거절될 수 있으므로, 거절되면 다른 모델로 한 번 더 보내는 API의 대체 기능을 켭니다.

**API에 보낸 내용은 모델 학습에 쓰이지 않습니다.** 2026-11-25에 Anthropic 공식 문서에서 확인했습니다. [상용 약관](https://www.anthropic.com/legal/commercial-terms)(2025-06-17 시행) B절은 API로 주고받은 입력과 출력으로 모델을 학습하지 않는다고 정합니다. 개인정보 안내 [Is my data used for model training?](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)(2026-08-18 갱신)도 API의 입력과 출력을 기본으로 학습에 쓰지 않는다고 적습니다. 예외는 사용자가 피드백을 직접 보냈거나 학습에 쓰도록 따로 허락한 경우뿐이고, 돌봄수첩에는 Anthropic에 피드백을 보내는 기능이 없습니다.

보관 기간은 [How long do you store my organization's data?](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)(2026-07-01 갱신)를 따릅니다. 입력과 출력은 받은 날부터 30일 안에 지웁니다. 다만 Anthropic의 자동 안전 검사에 걸린 요청은 입력과 출력을 최대 2년 보관합니다. 걱정 칸에는 약이나 자해처럼 검사에 걸릴 수 있는 말이 들어올 수 있으니, 보호자에게 보이는 안내에 "30일 뒤 모두 지워진다"처럼 예외 없이 적지 않습니다.

**실패했을 때.**

| 상황 | 화면 |
|---|---|
| 보충 질문을 만들지 못함 | 보충 질문을 건너뛰고 다음으로 갑니다 |
| 카드 고르기에서 API 오류, 15초 안에 응답 없음, 대체 모델까지 거절 | 6절의 규칙 기본 목록을 보여 주고, 화면 위에 "지금은 제안마다 맞춤 설명을 붙이지 못했어요. 제안은 그대로 살펴보실 수 있어요"를 띄웁니다 |
| 형식이 깨진 응답, 후보에 없는 카드 번호 | 잘못된 항목은 버립니다. 남은 항목이 3개보다 적으면 규칙 기본 목록으로 바꿉니다 |
| 질문의 답을 풀어 쓰지 못함 | 카드에 적힌 답 원문을 그대로 보여 줍니다 |
| 오늘 적은 내용을 쓰지 못함 | 상황별 질문과 보충 질문의 답을 "질문: 답" 줄로 그대로 나열합니다 |
| 의료진 질문에 약 이름, 복용량, 전화번호가 들어 있음 | 그 문장을 버립니다 |

기다리는 동안 "제안을 고르는 중이에요"를 보여 줍니다. HW6 점검에서는 목록 하나에 6～8초가 걸렸습니다.

## 8. 모든 화면에 적용하는 규칙

**응급 안내.** 11/25 회의에서 정했습니다. 첫 화면에서 응급인지 묻지 않습니다. 이미 119에 신고한 사람이 같은 질문에 다시 답하지 않게 하려는 것입니다. 대신 상황별 질문, 보충 질문, 걱정 칸에 직접 적은 글에 응급 신호(예: "불러도 대답이 없어요", "때리려고 해요", "죽고 싶다고 해요")가 있으면, 목록보다 먼저 119와 정신건강위기상담전화(1577-0199)를 띄웁니다. 폭력을 말하면 112, 죽음이나 자살을 말하면 자살예방상담전화(109)를 함께 보여 줍니다. 이 확인은 AI를 부르기 전에 브라우저에서 낱말로 하고, AI의 판단에 맡기지 않습니다. 모든 화면 아래에는 "위급할 때 연락처" 링크를 두어 같은 안내를 언제든 열 수 있게 합니다.

**의료 판단을 하지 않습니다.** 진단, 약 이름, 복용량, 증상 판단은 쓰지 않습니다. 증상과 약 주제의 답은 일반 정보와 다음 진료 때 물어볼 질문까지만 쓰고, 화면 위에 "참고만 하시고, 정확한 내용은 의료진과 상담하세요"를 붙입니다. 진료를 기다리지 말고 바로 연락해야 하는 신호는 공식 출처로 확인한 것만 그 주제 아래에 적습니다.

**결정을 대신하지 않습니다.** 돌봄 방법은 비교와 "잘 맞을 수 있음" 표시까지만 하고, 비교 화면 위에 "비교해 보시라고 나란히 놓았어요. 결정은 가족과 의료진이 함께 해 주세요."를 적습니다.

**확인 시점을 알립니다.** 처음 화면과 제안 아래에 내용을 확인한 달과 "신청하기 전에 공단(1577-1000)이나 안내된 기관에 꼭 확인해 주세요"를 보여 줍니다.

**온디바이스 원칙.** 보호자의 답과 결정은 보호자의 기기에서만 볼 수 있습니다. 돌봄 방법을 무엇으로 골랐는지, 무엇을 걱정하는지는 가족 안의 민감한 사정이기 때문입니다.

- 답, 기록, 고른 돌봄 방법, 그날 본 답, 체크, 돌보는 대상 칸, 글자 크기 설정은 그 휴대폰의 브라우저 저장소에만 둡니다.
- 로그인, 계정, 서버 저장, 다른 기기와의 동기화를 만들지 않습니다.
- 서버는 AI를 부를 때만 7절에 적은 내용을 받아 넘기고, 저장하거나 로그에 남기지 않습니다. 지난 기록과 고른 돌봄 방법은 서버로 보내지 않습니다.
- 방문 분석, 광고, 추적 스크립트를 넣지 않습니다.
- 기록을 밖으로 내보내는 길은 보호자가 직접 누르는 "카톡으로 보낼 글 복사" 하나뿐입니다.
- 그 대신 휴대폰을 바꾸거나 인터넷 사용 기록을 지우면 기록도 함께 지워집니다. 첫 화면과 "모든 기록 지우기" 앞에 이 점을 알리고, 남겨 두고 싶은 기록은 글로 복사해 두라고 안내합니다.

## 11. 만드는 방법과 완성 기준

**만드는 방법.** 통합 제품은 새 폴더 `app/`에 둡니다. `prototypes/`의 개인 프로토타입은 HW6 제출물이라 고치지 않습니다. `main`에 있는 김영균 HW6 버전(`prototypes/김영균/`)의 구조를 그대로 가져옵니다. Node 서버가 화면 파일을 내보내고, API 키를 서버에만 두고 Claude를 부릅니다. 규칙, AI 호출, 실패 처리, 사례 점검 코드가 출발점입니다. 서버를 올리고 관리하는 일과 API 비용은 김영균이 맡습니다.

AI를 빼고 만든 정적 버전([4kmba/ltc-caregivers#36](https://github.com/4kmba/ltc-caregivers/pull/36))은 기준으로 삼지 않습니다. 다만 그 버전에서 고친 카드 조건과 미리 써 둔 답은 내용 파일을 옮길 때 참고할 수 있습니다.

**자동 점검.** 다음을 테스트로 확인합니다.

- 내용 형식: 카드와 답이 가리키는 자료 번호가 모두 자료 목록에 있습니다.
- 확인 전 내용: 확인한 사람이 둘이 안 되는 자료를 가리키는 카드와 답이 후보에서 빠집니다.
- 규칙 기본 목록과 사례: AI를 끄고 인터뷰 요약 5건을 넣으면 단계가 맞고, 모든 제안에 출처가 있고, 인터뷰에서 막혔다고 말한 일의 카드가 들어갑니다. 돌봄 방법을 고른 경우를 사례마다 더합니다.
- AI 응답 검증: 후보에 없는 번호, 깨진 형식, 약 이름이 든 의료진 질문을 버립니다.
- 키 없이 켠 서버가 규칙 기본 목록과 카드 원문을 돌려줍니다.
- 응급 낱말

AI를 켠 사례 점검은 돌릴 때마다 결과가 조금씩 달라 자동 테스트에 넣지 않고, 손으로 두 번 이상 돌려 빠지는 카드를 적어 둡니다.

**손으로 하는 점검.** 휴대폰에서 직접 해 보고, 여덟 개 모두 통과해야 완성입니다.

1. **끝까지 가기.** "갑자기 넘어지셨어요"를 고르고 끝까지 답하면 방법 카드 3개가 나오고, 하나를 고르면 그날 날짜의 기록이 나오고 노랑 카드에는 제안 하나만 보입니다. 처음부터 기록을 받기까지 3분 안에 끝납니다.
2. **다시 묻지 않기.** 처음부터 다시 시작해 "증상이 나빠졌어요"를 고르면, 기본 정보를 새로 묻지 않고 저장된 답을 한 화면에 보여 줍니다.
3. **결정을 대신하지 않기.** 두 방법의 점수가 같아지도록 답하면 "잘 맞을 수 있음" 표시가 사라집니다. "방법은 나중에 정할게요"를 누르면 방법에 묶이지 않은 제안이 나옵니다.
4. **AI 없이 돌아가기.** API 키를 비우고 서버를 켜서 끝까지 가면, 보충 질문 없이 규칙 기본 목록과 "지금은 제안마다 맞춤 설명을 붙이지 못했어요. 제안은 그대로 살펴보실 수 있어요"가 나옵니다. 질문을 누르면 카드 원문이 나옵니다.
5. **AI가 지어내지 않기.** 걱정 칸에 "약을 끊어도 될까요?"를 적으면 "의료진에게 물어볼 질문"만 나오고, 끊어도 되는지에 대한 답은 어디에도 없습니다. 화면에 나온 전화번호와 링크를 모두 자료 목록과 대조하고, 질문 세 개를 눌러 풀어 쓴 답에 카드 원문에 없는 제도나 금액이 없는지 봅니다. AI 답은 매번 조금씩 다르므로 두 번 이상 돌립니다.
6. **응급 신호.** 걱정 칸에 "어제부터 불러도 대답이 없어요"를 적으면 119 안내가 목록보다 먼저 뜹니다. 어느 화면에서든 "위급할 때 연락처"를 눌러 같은 안내를 열 수 있습니다.
7. **기록과 다시 받기.** 질문 두 개를 열어 보고 제안 하나를 체크한 뒤 "상황이 바뀌었어요"로 답 하나를 바꾸면, 새 기록에 "지난번과 달라진 것"이 한 줄 나오고 체크가 남아 있습니다. 첫 화면의 지난 기록에 기록이 두 줄 보이고, 첫 기록을 열면 그날 본 답이 저장된 그대로 나옵니다.
8. **온디바이스.** 개발자 도구의 네트워크 기록을 켜고 7번을 다시 하면, 서버로 가는 요청에는 7절에 적은 내용만 있고 지난 기록, 고른 돌봄 방법, 체크는 없습니다. 다른 브라우저에서 같은 주소를 열면 지난 기록이 비어 있습니다. "카톡으로 보낼 글 복사"를 누르면 붙여 넣은 글에 날짜, 상황, 가장 먼저 살펴볼 제안, 연락할 곳이 들어 있습니다. "모든 기록 지우기" 뒤 새로고침하면 첫 화면이 비어 있습니다.

**사람에게 확인하기.** 인터뷰에 응해 준 보호자 몇 분께 보여 드리고 걸린 곳을 고칩니다. 사례 점검의 답은 인터뷰 요약과 만든 상황을 보고 고른 것이라, 실제 보호자가 직접 답한 결과가 아닙니다.
