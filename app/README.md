# 돌봄수첩 (통합 제품)

네 사람의 프로토타입을 한 제품으로 합친 돌봄수첩의 코드와 내용입니다. 기준 스펙은 [통합 스펙](../docs/specs/spec-integrated-care-plan.md)입니다. `prototypes/`의 개인 프로토타입은 HW6 제출물이라 고치지 않습니다.

내용 파일 다섯 개와 점검 코드, 처음부터 수첩 페이지까지 이어지는 화면과 서버, AI 호출 통로와 기능 틀, 팀원이 채울 AI 자리가 있습니다. 비교 화면과 심청이 그림은 팀원이 채울 자리로 비워 두었습니다.

## 내용 파일

화면은 `content/`의 다섯 파일을 읽기만 합니다. 내용을 고칠 때는 코드를 건드리지 않고 이 파일만 고쳐 PR을 올리면 됩니다.

| 파일 | 담는 것 | 어디서 왔나 |
|---|---|---|
| `situations.json` | 기본 정보 5화면, 상황 카드 8개와 상황별 질문, 답에 따라 붙는 질문, 주제 5개 | 김영균 질문, 백민경 상황과 꼬리 질문 |
| `methods.json` | 돌봄 방식 12개 (상황 4개에 3개씩) | 백민경 방식 9개, 입원·퇴원 방식 3개는 새로 씀 |
| `cards.json` | 할 일 카드 45장 | 김영균 정적 버전 카드 |
| `qa.json` | 질문과 답 195개 | 김영균 카드의 질문 180개, 한수연 FAQ 15개 |
| `sources.json` | 자료 99개 (출처 링크, 전화번호, 연락할 곳) | 김영균 출처 61개, 유정민 자료 20개, 한수연 출처 12개, 연락할 곳 |

연락처와 링크는 `sources.json`에만 적습니다. 카드와 답은 `source_ids`와 `contact_ids`로 자료 번호만 가리킵니다. 카드나 답의 글에 `1577-1000`처럼 전화번호를 적으면, 자동 점검이 그 번호가 자료 목록에 있는지 확인합니다.

## 검수하는 방법

**두 사람이 확인한 자료만 화면에 나옵니다.** 카드, 답, 방식은 가리키는 자료가 모두 확인돼야 나오고, 상황은 확인된 카드가 3장 이상(비교 화면이면 방식도 2개 이상) 있어야 나옵니다. 지금은 99개 가운데 1개만 두 사람이 확인해서 화면에 낼 수 있는 상황이 없습니다.

자료 하나를 확인하는 순서는 이렇습니다.

1. `sources.json`에서 자료를 찾아 `url`을 직접 열어 봅니다.
2. 이름, 기관, 전화번호, 요약이 페이지 원문과 맞는지 봅니다. 틀리면 고칩니다.
3. 그 자료를 가리키는 카드와 답(`cards.json`, `qa.json`에서 번호로 찾기)의 내용이 원문과 맞는지 봅니다.
4. `checks`에 이름과 날짜를 더합니다.

```json
"checks": [
  { "by": "김영균", "date": "2026-10-29" },
  { "by": "유정민", "date": "2026-11-27" }
]
```

같은 사람이 두 번 적으면 한 명으로 셉니다. 어느 상황을 누가 맡을지는 유정민, 백민경, 한수연 세 사람이 정합니다(스펙 5절).

## 점검 실행

Node 22.9 이상이 필요합니다. 처음 한 번 `npm install`로 Anthropic SDK를 설치합니다.

```bash
cd app && npm run check:content
```

확인된 자료 수, 상황별로 화면에 나올 수 있는 카드와 방식 수, 확인이 더 필요한 자료(쓰는 곳이 많은 순)를 표로 보여 줍니다. 번호가 틀린 곳이 있으면 목록을 띄우고 실패로 끝납니다.

```bash
cd app && npm test
```

번호 점검과 함께, 확인이 한 명뿐인 자료를 가리키는 카드가 빠지는지와 글에 적힌 전화번호가 자료 목록에 있는지를 테스트합니다.

## AI 자리

AI 기능은 모두 `src/ai/task.mjs`의 `runTask`를 지납니다. `prompts/<이름>.md`가 아직 없으면 AI를 부르지 않고 대체 값(스펙 7절)을 돌려주며, 이때 reason은 `not_built`입니다. 그래서 프롬프트 파일을 만드는 순간부터 그 기능의 AI가 켜집니다. 모든 기능에 붙는 공통 지시는 `prompts/common.md`에 있고, B1 담당이 여기에 말투를 더합니다.

팀원이 채울 자리는 아래와 같습니다. 입력과 값은 11/28에 맡은 사람과 확정합니다. 입력을 바꾸면 자리 파일, 브라우저가 보내는 칸 표(`public/app.js`의 `SEND`), 화면 세 곳을 함께 고쳐야 합니다.

AI가 쓴 글에서는 전화번호와 링크가 든 문장을 `src/ai/sanitize.mjs`의 `stripUnsafe`가 지웁니다. 카드 고르기의 "왜 지금", 오늘 정리, 질문 답이 이 점검을 지나고, 다 지워져 남는 글이 없으면 대체 값으로 갑니다.

| 자리 | 파일과 만드는 함수 | 화면 위치 | 입력 | 값 | 대체 값 (스펙 7절) |
|---|---|---|---|---|---|
| 본보기: 카드 고르기 | `src/tasks/pick-cards.mjs`, `makePickCards(content)` | 수첩 페이지의 할 일 목록 (`public/app.js`의 `buildPage`가 부름) | `{ situation, answers, methodId, worry, followups: [{ q, a }] }` | `{ items: [{ card_id, bucket, why }] }` | 규칙 기본 목록 |
| A1 보충 질문 | `src/tasks/followups.mjs`, `makeFollowups(content)` | 질문 화면의 보충 질문 (`public/screens/questions.mjs`의 `renderFollowups`) | `{ situation, answers }` | `[{ q, options: string[] }]` 2개까지 | `[]` (건너뜀) |
| B2 오늘 정리 | `src/tasks/summary.mjs`, `makeSummary(content)` | 수첩 페이지의 "오늘 정리한 내용" (`public/screens/page.mjs`, 값은 `buildPage`가 채움) | `{ answered: [{ q, a }], followups: [{ q, a }], worry }` | 글 한 덩이 | 답을 `"질문: 답"` 줄로 나열 |
| B3 질문에 답하기 | `src/tasks/answer.mjs`, `makeAnswer(content)` | 수첩 페이지의 질문 카드 (`public/screens/page.mjs`) | `{ qaId, answers }` | 글 한 덩이 | `qa.json`에 적힌 답 원문 |
| B4 의료 질문 돌려 주기 | `src/tasks/medical.mjs`, `makeMedical(content)` | 수첩 페이지의 "다음 진료 때 의료진에게 물어볼 질문" (`public/screens/page.mjs`, 값은 `buildPage`가 채움) | `{ worry }` | `string[]` 2개까지 | `[]` |

### 기능 하나 만드는 법

1. `evals/<이름>.jsonl`에 시험 질문을 3～5개 먼저 적습니다. 한 줄의 모양은 `{ "id", "input", "mustNotInclude": [], "mustIncludeAny": [] }`입니다.
2. `prompts/<이름>.md`를 만듭니다. 만드는 순간 AI가 켜집니다.
3. 필요하면 `src/tasks/<이름>.mjs`의 `buildUser`와 `validate`를 고칩니다.
4. `npm run eval -- <이름> [횟수=2]`를 두 번 이상 돌려 통과할 때까지 프롬프트를 고칩니다. 이 명령은 실제 API를 불러서 돈이 듭니다.
5. `npm test`가 통과하면 PR을 올립니다.

### 키 없이 개발하기와 키 확인하기

키는 환경 변수 `ANTHROPIC_API_KEY`에만 둡니다. 코드에 적지 않고, `.env.example`에는 변수 이름만 있습니다.

- 키 없이 개발하기: `SHOW_UNVERIFIED=1 npm start`로 확인 전 내용을 화면에 띄워 개발합니다.
- 서버 주소 바꾸기: `HOST`(기본 127.0.0.1, 컨테이너에서는 0.0.0.0)와 `PORT`(기본 8787) 환경 변수로 정합니다.
- 키가 되는지 확인하기: `npm run try-call`이 자기 키로 AI를 한 번 불러 봅니다.
- 키를 받는 법: 팀이 정하면 채웁니다(#44).

## 옮기면서 바꾼 것

검수할 때 아래 항목을 함께 봐 주세요. 모두 김영균이 옮기면서 정한 초안입니다.

**카드를 일곱 상황으로 나눴습니다.** 원래 카드는 돌봄 단계 네 개로 나뉘어 있었습니다. "입원·낙상·악화 뒤 다시 정하기" 단계의 카드 32장은 낙상, 증상 악화, 입원·퇴원 가운데 맞는 상황에 다시 표시했고, 주 보호자가 돌볼 수 없게 됨과 잘 모르겠어요에는 맞는 카드를 골라 넣었습니다. 카드마다 `situations`에 적혀 있습니다.

**기본 정보에서 뺀 질문을 쓰던 카드 조건을 바꿨습니다.** 스펙 4절에서 나이, 한 달 예산, 분담 방식, 돌보는 시간을 질문에서 뺐기 때문입니다.

| 카드 | 바꾼 조건 |
|---|---|
| S1-11 노인맞춤돌봄 | 65세 이상 조건을 뺌 |
| S2-06 가족요양 | 돌보는 시간 대신 "함께 산다" |
| S3-07 가족회의 | 분담 방식 조건을 빼 모든 해당 상황에 나옴 |
| S3-11 출퇴근 공백 | 돌보는 시간 대신 "평일 낮에 곁에 있을 가족 없음" |
| S4-04 시설 비용 | 한 달 예산 대신 비용 부담 "큼, 보통, 잘 모르겠어요" |

상황을 기준으로 바꾼 조건도 있습니다. S3-05(넘어진 뒤 신호)는 골절 진단 조건을 빼고 낙상 상황에만 두었고, S3-10(증상이 갑자기 나빠짐)은 치매 진단 조건을 뺐습니다. S3-01, S3-03, S3-04, S3-08은 입원·퇴원 상황을 골랐거나 낙상 상황에서 "입원했어요"라고 답하면, 기본 정보에서 입원 중을 고르지 않았어도 입원 중으로 봅니다. S3-06(집 안 정리)은 낙상 상황이면 거동과 상관없이 후보에 넣습니다.

**연락할 곳은 자료 번호로 바꿨습니다.** 카드의 연락할 곳 문장은 `contact_note`에 그대로 두고, 문장에 나오는 기관과 전화번호를 찾아 `contact_ids`에 자료 번호로 적었습니다. 주민센터, 병원 사회복지팀, 주치의, 이용하는 기관처럼 링크가 없는 곳은 `kind: "place"`인 자료로 넣었습니다.

**돌봄 방식은 답 이름만 바꿨습니다.** 백민경 방식의 점수 규칙을 새 질문의 답으로 옮겼습니다. 예를 들어 "주 보호자의 일: 전일 근무"는 "일을 해요"로 바꿨습니다. 비용은 스펙 5절에 따라 공식 기준만 남기고 "낮음, 중간, 높음"은 뺐습니다. 오늘과 이번 주 할 일 문장은 맞는 카드 번호(`first_cards`)로 바꿨고, 맞는 카드가 없는 문장(예: 가족 단체방에 교대 일정 올리기)은 옮기지 않았습니다.

**입원·퇴원 방식 세 개는 새로 썼습니다.** 스펙 4절에서 새로 쓰기로 한 부분입니다. 백민경 낙상 방식의 문장과 김영균 입원 카드에서 가져와 썼고, 아직 아무도 검수하지 않았습니다.

**확인 기록은 실제로 남은 것만 옮겼습니다.** 김영균 출처는 김영균이, 유정민 자료는 유정민이 확인한 날짜를 옮겼습니다. 같은 링크를 두 사람이 따로 확인한 노인장기요양보험 누리집(`ltc`)만 두 사람 확인이 됐습니다. 한수연 출처와 연락할 곳은 확인 날짜가 적혀 있지 않아 비워 두었습니다.

## 검수하면서 정해야 할 것

옮긴 내용끼리 맞춰 보다가 찾은 것입니다. 사실을 확인해야 하는 일이라 옮기면서 고치지 않았습니다.

- **가족휴가제 일수가 서로 다릅니다.** 한수연 FAQ(`faq-me-1`)는 2025년 8월 기준으로 단기보호 1년 11일, 12시간 방문요양 22회라고 적었습니다. 김영균 카드(S2-09, S3-11, S4-09, C-01)와 유정민 자료(`ltc_family_leave`)는 단기보호 12일, 종일 방문요양 24회입니다. 공단 누리집에서 지금 기준을 확인해 한쪽으로 맞춰야 합니다.
- **같은 질문이 두 번 나옵니다.** "요양원과 요양병원은 무엇이 다른가요?"가 카드 S4-02의 질문(`S4-02-q1`)과 한수연 FAQ(`faq-place-1`)에 모두 있어, 주제별 화면의 "기관 고르기"에 두 번 나옵니다. 하나를 지우거나 답을 합쳐야 합니다.
- **카드 없이 읽으면 뜻이 흐린 질문이 있습니다.** "누가 받을 수 있나요?"(`S1-05-q1`, `S1-11-q1`)처럼 카드 제목을 봐야 뜻이 통하는 질문은 주제별 화면에서 무엇을 묻는지 알기 어렵습니다. 질문에 대상을 넣어 고치거나, 화면에서 카드 제목을 함께 보여 줘야 합니다.

## 아직 채우지 않은 것

- 걱정돼 알아보는 중, 등급 직후 상황의 상황별 질문과 지켜볼 신호. 스펙 4절에 따라 카드를 상황별로 나누면서 정합니다.
- 시설을 생각 중이에요(P1)의 돌봄 방식
